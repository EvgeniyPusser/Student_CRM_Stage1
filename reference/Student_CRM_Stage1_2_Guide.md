# Student CRM — подготовка Windows и развёртывание проекта с нуля

Дата инструкции: 19 ноября 2026 года.  
Для сборки: Student CRM Stage 1, версия приложения 0.2.0, ТЗ 1.3.  
Формат: базовый Markdown. Команды рассчитаны на Windows PowerShell.

## 1. Что получится в конце

На вашем компьютере будут работать MySQL и сервер Express с интерфейсом React. Вы откроете http://localhost:8080, войдёте администратором, создадите группу, пригласите студента и проверите его кабинет. Записи сохраняются в базе, а не только в браузере.

Эта инструкция доводит до настоящего локального развёртывания первого этапа. Интернет-публикация для реального учебного центра — отдельный последующий этап: в текущей сборке ещё нет полного набора функций запуска, включая 2FA, почтовые процессы и резервирование по расписанию. APP_ENV=production намеренно заблокирован.

Существующий автономный Student_CRM_Offline.html — отдельный прототип. Он не нужен для установки этой сборки и не подключается к её базе.

## 2. Общая последовательность

1. Проверить Windows, память, свободное место и виртуализацию.
2. Установить или обновить WSL 2, перезагрузить компьютер.
3. Установить Docker Desktop, включить Linux-контейнеры и проверить движок.
4. Установить Node.js в Windows.
5. Скачать и распаковать Student_CRM_Stage1.zip.
6. Создать файл .env командой проекта.
7. Собрать и запустить контейнеры.
8. Создать вымышленные учебные данные.
9. Открыть сайт и проверить три кабинета.
10. Научиться останавливать проект и сохранять копию базы.

Не вводите все команды сразу. После каждого этапа выполните его контрольную проверку.

## 4. Проверить компьютер

### 4.1. Windows и архитектура

Основной маршрут — современная поддерживаемая Windows 11 на обычном 64-битном компьютере Intel/AMD. Нажмите Win + R, введите winver и нажмите Enter. Запишите версию и сборку.

Откройте «Параметры → Система → О системе». В строке «Тип системы» ожидается 64-разрядная Windows и процессор x64. Если указан ARM, остановитесь перед выбором установщиков: для него нужны другие пакеты и отдельная проверка совместимости образов проекта.

Точные требования текущего Docker Desktop к выпускам и редакциям Windows проверяйте на официальной странице [1]. Наличие WSL само по себе не подтверждает совместимость Docker Desktop. Для Windows 10 сначала проверьте поддержку вашей версии; не устанавливайте случайную старую сборку Docker как универсальное решение.

### 4.2. Память и диск

У Docker Desktop есть аппаратные требования, включая минимум 8 ГБ RAM для указанного WSL-маршрута [1]. Для комфортной работы этого проекта рекомендую 16 ГБ RAM и не менее 25–30 ГБ свободного места под образы, сборку и базу. Последние числа — практический запас для проекта, а не официальный минимум Docker.

Свободное место видно в «Проводник → Этот компьютер». Интернет нужен для скачивания установщиков и первой сборки. Перезагрузки потребуются при настройке Windows/WSL.

### 4.3. Виртуализация

Нажмите Ctrl + Shift + Esc, откройте «Производительность → ЦП». Найдите «Виртуализация»; ожидается «Включено».

Если она выключена, её включают в BIOS/UEFI. Название зависит от производителя: Intel Virtualization Technology, VT-x, AMD-V или SVM Mode. Точный вход в BIOS и нужный пункт ищите в руководстве вашей модели. Если компьютер рабочий, обратитесь к IT. Менять наугад другие настройки BIOS не нужно.

## 5. В каком окне вводить команды

Используем PowerShell в Windows. Не вводите эти команды в адресную строку браузера, консоль JavaScript, MySQL или Ubuntu.

Чтобы открыть обычное окно: нажмите «Пуск», введите PowerShell и откройте Windows PowerShell. В Windows Terminal можно выбрать вкладку Windows PowerShell.

Ожидаемый вид приглашения:

```text
PS C:\Users\YourName>
```

Это приглашение показывает текущую папку; его не нужно копировать. Из блоков ниже копируйте только команды. Вставьте команду в PowerShell и нажмите Enter. Новую команду вводите после возвращения строки PS ...>.

Для установки WSL используйте окно администратора: правой кнопкой по PowerShell → «Запуск от имени администратора». Обычная работа с проектом дальше выполняется без повышенных прав.

## 6. Установить или обновить WSL 2

WSL означает Windows Subsystem for Linux. В этой инструкции Linux нужен как основа Docker, а работать с проектом мы будем из Windows.

### 6.1. Проверить, что уже установлено

Откройте PowerShell от имени администратора и выполните:

```powershell
wsl --status
wsl --version
```

Если WSL уже есть, не удаляйте существующие дистрибутивы. Выполните обновление:

```powershell
wsl --update
wsl --set-default-version 2
```

### 6.2. Если WSL не установлен

Для этой схемы не требуется отдельная Ubuntu. Можно установить WSL без пользовательского Linux-дистрибутива [3]:

```powershell
wsl --install --no-distribution
```

Если эта опция недоступна в вашей Windows, используйте стандартный маршрут Microsoft [2]:

```powershell
wsl --install
```

Стандартный вариант обычно добавляет Ubuntu. Это допустимо и не мешает проекту. После установки перезагрузите компьютер через меню Windows. Если был установлен Ubuntu и он запросит Linux-имя пользователя и пароль, это отдельная локальная учётная запись Ubuntu, не ваш пароль CRM; внутри Ubuntu для данного маршрута ничего устанавливать не нужно.

После перезагрузки откройте PowerShell и выполните:

```powershell
wsl --update
wsl --set-default-version 2
wsl --version
wsl --status
```

Ориентируйтесь на актуальную версию WSL; официальный минимальный уровень для Docker сверяйте с [4]. Если Microsoft Store заблокирован и обновление выдаёт ошибку, документация WSL описывает вариант wsl --update --web-download [3]. Используйте его при такой конкретной проблеме, а не запускайте все варианты подряд.

Команда wsl --list --verbose показывает установленные пользовательские дистрибутивы и их версии. При установке без Ubuntu отсутствие пользовательского дистрибутива само по себе не означает, что основа WSL для Docker не установлена.

## 7. Установить Docker Desktop

1. Откройте официальную страницу [1].
2. Выберите установщик для Windows x86_64, если у вас Intel/AMD x64.
3. Запустите скачанный установщик. При запросе Windows подтвердите установку.
4. Если есть выбор движка, выберите WSL 2. Для этого проекта не выбирайте Windows containers.
5. Завершите установку; перезагрузите компьютер, если установщик попросит.
6. Откройте Docker Desktop через «Пуск».
7. Прочитайте показанные условия использования; если устанавливаете в компании, применимость лицензии определяет сама компания.
8. Если предлагается вход в Docker-аккаунт, он не является учётной записью CRM. Для обычного локального запуска можно пропустить вход, если интерфейс даёт такую возможность; при ограничениях скачивания образов аккаунт реестра может понадобиться.
9. Дождитесь состояния готового движка, например Engine running.

В Docker Desktop откройте Settings → General. Если доступен пункт Use WSL 2 based engine, он должен быть включён. В некоторых версиях он включён по умолчанию и отдельно не показывается [4].

Нам нужны Linux-контейнеры. Если меню Docker предлагает «Switch to Linux containers», переключитесь на Linux. Если предлагает «Switch to Windows containers», обычно это означает, что сейчас уже выбран Linux.

Для команд из PowerShell включать интеграцию конкретной Ubuntu необязательно. Не устанавливайте параллельно отдельный Docker Engine внутри Ubuntu для этого маршрута.

### 7.1. Проверка Docker

Закройте старое окно PowerShell и откройте новое обычное окно:

```powershell
docker --version
docker compose version
docker version
```

Первые две команды подтверждают наличие командных инструментов. В docker version должны быть доступны не только Client, но и Server. Если Server недоступен, движок ещё не запущен.

Дополнительная проверка:

```powershell
docker run --rm hello-world
```

Ожидается демонстрационное сообщение Hello from Docker! При первом запуске скачивается небольшой образ. Эта проверка выполняется отдельно от CRM и не создаёт учебные данные.

## 8. Установить Node.js в Windows

Откройте официальный сайт [5]. Для данного маршрута можно выбрать Windows Installer (.msi), ветку 24.x LTS и архитектуру x64. Наш скрипт настройки требует Node.js 22 или новее; ветка 24 уже использовалась при проверке серверного этапа. Внутри Dockerfile проекта отдельно закреплена ветка Node.js 22 — это не конфликт с Windows-установкой.

В установщике оставьте обычные компоненты, включая Add to PATH и npm. Если предлагается необязательная установка инструментов для сборки native modules через дополнительные пакеты, для этого Docker-маршрута она не требуется: зависимости проекта собираются внутри контейнера.

Закройте PowerShell, откройте новое окно и проверьте:

```powershell
node --version
npm.cmd --version
```

Ожидаются номера версий, например v24.x.x и номер npm. npm.cmd использован намеренно: на некоторых Windows прямой вызов npm попадает на PowerShell-скрипт, выполнение которого ограничено политикой системы. Менять системную ExecutionPolicy для запуска нашего проекта не нужно.

## 9. Подготовить папку и скачать проект

Рекомендую простую папку вне OneDrive и системных каталогов, например C:\Projects. Не распаковывайте проект в C:\Program Files или внутрь самого ZIP.

Создать папку можно Проводником. Если создание C:\Projects ограничено, используйте папку внутри своего профиля, например C:\Users\YourName\Projects; дальше замените путь в командах на свой.

Скачайте актуальный Student_CRM_Stage1.zip из ответа с файлами. В Проводнике нажмите по ZIP правой кнопкой → «Извлечь всё» и укажите C:\Projects как папку назначения. Архив уже содержит верхнюю папку Student_CRM_Stage1.

Итоговая рабочая папка должна содержать:

```text
C:\Projects\Student_CRM_Stage1
```

Внутри неё должны быть compose.yaml, Dockerfile, README.md и папки client, server, scripts, docs. Если получилась двойная вложенность Student_CRM_Stage1\Student_CRM_Stage1, рабочая папка — та, где находится compose.yaml.

Включите показ расширений файлов в Проводнике: «Вид → Показать → Расширения имён файлов» или аналогичный пункт вашей версии Windows. Это поможет отличать .env от ошибочно созданного .env.txt.

## 10. Открыть PowerShell в правильной папке

В обычном PowerShell выполните:

```powershell
Set-Location 'C:\Projects\Student_CRM_Stage1'
Get-Location
Test-Path .\compose.yaml
Test-Path .\scripts\setup.mjs
```

Ожидается ваш путь и два ответа True. При False сначала исправьте путь; пока не запускайте Docker Compose.

В дальнейшем все команды Docker Compose вводятся из этой папки. Не переходите в server или client для обычного запуска.

## 11. Создать настройки .env

Выполните:

```powershell
node .\scripts\setup.mjs
Test-Path .\.env
```

Скрипт создаёт .env со случайными паролями. Проверка должна вернуть True. Если .env уже существует, скрипт оставляет его без изменений. Это защищает настройки повторного запуска.

Для просмотра у себя на компьютере:

```powershell
notepad .\.env
```

В файле будут строки вида:

```dotenv
APP_ENV=demo
APP_ORIGIN=http://localhost:8080
COOKIE_SECURE=false
LOCAL_INVITES=true
DB_NAME=student_crm
DB_USER=crm
DB_PASSWORD=<случайное значение, созданное скриптом>
MYSQL_ROOT_PASSWORD=<другое случайное значение>
DEMO_PASSWORD=<пароль учебных аккаунтов>
```

Этот блок показывает смысл настроек. Не заменяйте им созданный файл: значения в угловых скобках не являются рабочими паролями.

| Настройка | Значение для первого запуска |
| --- | --- |
| APP_ENV | demo; production пока не включать |
| APP_ORIGIN | http://localhost:8080; должен совпадать с адресом в браузере |
| COOKIE_SECURE | false для локального HTTP; это не настройка будущего HTTPS-сервера |
| LOCAL_INVITES | true; код приглашения выдаётся в учебном интерфейсе вместо письма |
| DB_NAME | student_crm |
| DB_USER | crm |
| DB_PASSWORD | Пароль доступа приложения к базе |
| MYSQL_ROOT_PASSWORD | Отдельный пароль администратора MySQL |
| DEMO_PASSWORD | Первоначальный пароль вымышленных аккаунтов CRM |

Сохраните .env отдельно от публичного архива и не отправляйте его в чат или на скриншоте. Редактирование DB_PASSWORD после создания базы не меняет пароль уже существующего пользователя MySQL. Изменение DEMO_PASSWORD после создания учебных аккаунтов также не меняет их пароли в базе.

## 12. Собрать и запустить проект

Docker Desktop должен быть запущен. Выполните:

```powershell
docker compose config --quiet
```

При успехе команда может ничего не вывести. Она проверяет конфигурацию, но не подтверждает, что приложение уже работает. Если сообщает об отсутствующей переменной, проверьте .env и текущую папку.

Затем:

```powershell
docker compose up --build -d
```

Значение параметров: --build собирает приложение по Dockerfile; -d оставляет контейнеры работать в фоне [6]. При первой сборке скачиваются образы MySQL и Node.js, устанавливаются зависимости и собирается React. Это может занять несколько минут и дольше при медленном интернете.

Не закрывайте Docker Desktop и не запускайте повторную сборку, пока текущая команда ещё выполняется. Дождитесь возвращения приглашения PowerShell.

Посмотрите результат:

```powershell
docker compose ps -a
docker compose logs --tail=100 migrate
docker compose logs --tail=100 app
```

В проекте три сервиса:

| Сервис | Нормальное состояние после первого запуска |
| --- | --- |
| db | Работает; проверка здоровья — healthy |
| migrate | Завершился с кодом 0; это одноразовое создание/обновление таблиц |
| app | Работает и слушает порт 8080 |

migrate не обязан постоянно быть Running. Сообщение Exited (0) для него нормально. Exited (1) или другой ненулевой код — ошибка: сначала смотрите его журнал. Docker Compose умеет показывать завершившиеся сервисы через ps -a [7].

## 13. Загрузить учебные данные

Только после успешной миграции и старта app выполните:

```powershell
docker compose exec app npm run seed
```

Здесь npm выполняется внутри Linux-контейнера. Поэтому в этой команде используется npm, а не Windows npm.cmd.

Команда создаёт вымышленные аккаунты, курс, группы и примеры занятий. Повторный seed сохраняет существующие пароли и не является командой полного сброса базы. После начала собственной работы он не заменяет импорт и не удаляет ваши изменения.

## 14. Проверить, что сервер действительно работает

В PowerShell:

```powershell
Invoke-RestMethod 'http://localhost:8080/api/v1/health'
```

Ожидаются значения status: ok, stage: 1, database: mysql. Этот ответ проверяет обращение сервера к MySQL, а не просто наличие открытой страницы.

Затем откройте Edge, Chrome или Firefox и введите в адресную строку:

```text
http://localhost:8080
```

Используйте именно http и localhost. Адрес http://127.0.0.1:8080 технически указывает на тот же компьютер, но отличается Origin; при неизменённом APP_ORIGIN вход и изменяющие действия по нему будут отклоняться. https://localhost:8080 в этой локальной сборке не настроен.

localhost означает ваш собственный компьютер. Этот адрес на телефоне указывает на телефон, а не на Windows-компьютер.

## 16. Пройти полный проверочный сценарий

### 16.1. Курс и группа

В кабинете администратора откройте «Курсы» и создайте тестовый курс. В «Моих группах» нажмите «Создать группу». Укажите курс, уникальный код, название, преподавателя и даты; дата окончания не раньше начала. Для первых проб можно выбрать вместимость 5 человек.

Сохраните и откройте группу. Запись должна остаться после обновления страницы.

### 16.2. Приглашение студента

В разделе студентов создайте вымышленную карточку: имя, фамилию и уникальный email, например learner01@example.com. Телефон необязателен. Если заполняете, используйте международную форму с + и кодом страны; вымышленные номера могут не пройти проверку плана нумерации, поэтому для первой пробы телефон можно оставить пустым.

После сохранения откроется код приглашения. В этой учебной сборке настоящее письмо не отправляется. Код действует 72 часа и используется один раз.

В отдельном браузере или приватном окне откройте http://localhost:8080, нажмите «У меня есть приглашение», вставьте код и установите пароль не короче 12 символов. Затем войдите с email приглашённого студента и установленным паролем.

### 16.3. Зачисление

Вернитесь в кабинет администратора, откройте созданную группу и нажмите «Зачислить студента». Выберите его и дату начала. Для активного обучения в группе в состоянии «обучение» укажите сегодняшнюю дату или прошедшую. Будущая дата создаёт запланированное зачисление.

Повторное зачисление той же пары в текущем этапе возвращает конфликт; возобновление старых периодов будет добавлено позже. Вместимость группы проверяется сервером.

### 16.4. Занятие

В расписании администратора нажмите «Добавить занятие». Выберите нужную группу и того преподавателя, который назначен этой группе. Укажите тему, дату, начало и окончание. Для онлайн-формата нужна HTTPS-ссылка; для очного — аудитория/адрес.

В первом серверном этапе смещение Израиля указывается явно: UTC+02:00 для зимнего времени, UTC+03:00 для летнего. Смещение проверяется по дате. Если сервер пишет, что оно не соответствует дате, исправьте смещение; не меняйте часы компьютера. На датах перевода часов возможны неоднозначные или несуществующие местные времена; обычные дневные/вечерние занятия удобнее для первой проверки.

При пересечении занятия группы или преподавателя сервер отклонит сохранение. Выберите свободное время. Для просмотра используйте нужную неделю; порядок дней — воскресенье–суббота в RU/EN и всех ролях.

### 16.5. Студент и преподаватель

Обновите кабинет зачисленного студента: он должен видеть свою группу и её расписание, но не список контактов других студентов. Преподаватель видит назначенные ему группы и их состав. Изменение ID чужой группы в запросе не даёт доступа к ней.

Переключите RU/EN. Язык применяется сразу и сохраняется в профиле.

## 17. Убедиться, что данные не исчезают

Создайте тестовую запись, запомните её название, затем выполните:

```powershell
docker compose restart app
```

Дождитесь запуска и обновите страницу. Запись должна остаться: база находится в отдельном контейнере и сохраняемом томе.

Для более полной проверки остановите проект и снова поднимите его по разделу 18. После входа проверьте запись повторно. Хранение в томе защищает от обычного пересоздания контейнера, но не является резервной копией при поломке диска или удалении тома.

## 18. Повседневный запуск и остановка

После перезагрузки Windows сначала запустите Docker Desktop и дождитесь готовности движка. Затем откройте PowerShell в папке проекта:

```powershell
Set-Location 'C:\Projects\Student_CRM_Stage1'
docker compose up -d
```

Для ежедневного запуска повторять setup и seed не требуется. up -d подходит и когда контейнеры были удалены без удаления тома.

Остановить проект:

```powershell
docker compose stop
```

После этого можно закрыть Docker Desktop. Закрытие браузера само по себе не останавливает контейнеры.

Команда docker compose down удаляет контейнеры и сеть, но по умолчанию оставляет именованные тома [8]. Не добавляйте параметр -v и не удаляйте том crm_mysql в Docker Desktop, если нужно сохранить базу. Команды очистки с удалением volumes не являются способом устранения обычной ошибки запуска.

## 19. Где лежат данные и что сохранить

Код находится в распакованной папке. Настройки и первоначальные пароли — в .env. Файлы MySQL находятся в Docker volume, описанном как crm_mysql. При стандартном имени Compose-проекта фактическое имя обычно student-crm-stage1_crm_mysql; используйте список, а не догадку:

```powershell
docker volume ls
```

Копирование папки проекта на другой компьютер не переносит базу из Docker volume. Для переноса нужны код, .env и дамп MySQL. Пароль базы в .env должен соответствовать восстановленной конфигурации.

Не запускайте две независимые копии этой сборки с одинаковым фиксированным Compose-именем, рассчитывая получить две отдельные базы: в compose.yaml задано name: student-crm-stage1.

## 20. Создать ручную резервную копию базы

Перед копированием завершите действия в браузере. В обычном PowerShell из папки проекта:

```powershell
New-Item -ItemType Directory -Force .\backups | Out-Null
```

Затем выполните одну строку:

```powershell
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump -u "$MYSQL_USER" --single-transaction --no-tablespaces --set-gtid-purged=OFF "$MYSQL_DATABASE" > /tmp/student-crm-backup.sql'
```

Если команда завершилась без ошибки, скопируйте дамп из контейнера:

```powershell
$backupFile = '.\backups\student-crm-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sql'
docker compose cp db:/tmp/student-crm-backup.sql $backupFile
Get-Item $backupFile
```

Ожидается файл с ненулевым размером. Дамп формируется внутри Linux-контейнера и копируется как файл: так мы не зависим от различий кодировки перенаправления вывода в Windows PowerShell. Параметр single-transaction даёт согласованный снимок InnoDB при отсутствии одновременных изменений структуры таблиц; не совмещайте эту процедуру с миграцией.

Сохраните дамп и приватную копию .env на отдельном защищённом носителе. Эти файлы содержат данные и секреты, их не нужно прикладывать к обычным вопросам об ошибках.

Наличие SQL-файла не подтверждает восстановимость. Восстановление сначала проверяют на отдельной тестовой базе; импорт дампа в текущую базу может перезаписать данные. Автоматический бэкап, тест восстановления и перенос на новый компьютер будут оформлены отдельным этапом. Здесь не предлагается выполнять разрушительный импорт вслепую.

Не заменяйте папку целиком поверх работающих данных без подготовки.

1. Создайте копию базы по разделу 20 и сохраните .env.
2. Прочитайте описание конкретного обновления и его миграций.
3. Остановите приложение, оставив базу:


4. Обновите исходные файлы в той же рабочей папке, сохранив свой .env.

## 22. Частые проблемы

| Симптом | Что означает и что делать |
| --- | --- |
| docker не распознана | Установить Docker Desktop; открыть новое окно PowerShell после установки |
| node не распознана | Проверить установку Node.js и PATH; открыть новое окно PowerShell |
| npm.ps1 запрещён политикой | Для проверки на Windows использовать npm.cmd; Compose-команды не требуют изменения ExecutionPolicy |
| Docker Client есть, Server недоступен | Запустить Docker Desktop и дождаться готовности; смотреть его сообщение об ошибке |
| WSL needs updating | Выполнить wsl --update и перезапустить компьютер/Docker по указанию установщика |
| Виртуализация недоступна | Проверить её состояние в Диспетчере задач и настройки BIOS/UEFI вашей модели |
| no configuration file provided | Открыта неправильная папка; найти compose.yaml и перейти в неё |
| Missing DB_PASSWORD или похожая ошибка | Выполнить setup.mjs из этой сборки и проверить .env; не копировать пример с пустыми паролями |
| Виден .env.txt | Это другое имя; используйте файл .env, созданный скриптом |
| db unhealthy | Посмотреть docker compose logs --tail=100 db; не удалять том как первый шаг |
| migrate Exited (0) | Нормальное успешное завершение одноразового сервиса |
| migrate Exited с ненулевым кодом | Ошибка миграции; изучить журнал migrate, не продолжать seed |
| Ошибка скачивания образа, timeout или 429 | Проверить интернет и сообщение Docker; лимит реестра иногда требует входа в реестр или ожидания; не скачивать образы со случайных зеркал |
| localhost:8080 не открывается | Проверить docker compose ps -a, журнал app и health; убедиться, что Docker работает |
| invalidOrigin при входе | Открыть именно http://localhost:8080; сверить APP_ORIGIN |
| csrf или ошибка сеанса формы | Обновить страницу и войти заново |
| invalidCredentials | Проверить email, выполнение seed и первоначальный DEMO_PASSWORD; изменение строки .env не меняет пароль уже созданного аккаунта |
| Приложение видит старую базу после смены паролей | Том сохраняется; вернуть согласованные настройки, не удалять данные автоматически |
| Смещение Израиля не соответствует дате | Выбрать корректное UTC+02:00/UTC+03:00 для даты занятия |
| Ошибка APP_ENV=production | Это предусмотренный запрет первого этапа; оставить demo для учебного запуска |

### 22.1. Если порт 8080 занят

Проверить в PowerShell:

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen -ErrorAction SilentlyContinue
```

Не завершайте неизвестные процессы наугад. Если порт занят вашей другой программой, можно её штатно закрыть. Альтернатива — согласованно сменить внешний порт этой CRM.

В compose.yaml замените строку:

```yaml
- "127.0.0.1:8080:8080"
```

на:

```yaml
- "127.0.0.1:8081:8080"
```

Первый порт относится к Windows, второй — к контейнеру. В .env замените APP_ORIGIN на http://localhost:8081. Затем выполните:

```powershell
docker compose up -d --force-recreate app
```

Открывайте http://localhost:8081. В командах проверки health также используйте 8081. Одного изменения адреса в браузере недостаточно.

### 22.2. Как собрать информацию об ошибке

В папке проекта выполните:

```powershell
docker compose ps -a
docker compose logs --tail=80 app
docker compose logs --tail=80 migrate
docker compose logs --tail=80 db
```

Для разбора нужны текст ошибки и команда, после которой она появилась. Перед отправкой уберите реальные данные и секреты. Не отправляйте .env и полный вывод docker compose config: он может содержать подставленные пароли.

## 23. Что значит «развёрнуто» и что ещё впереди

Локальное развёртывание успешно, когда Docker работает, db имеет статус healthy, migrate завершён с кодом 0, app отвечает на health, три учебных аккаунта входят, студент видит свою группу, а запись сохраняется после перезапуска приложения.

В текущем compose.yaml порт опубликован только на 127.0.0.1. Поэтому доступ с другого компьютера, телефона и из интернета не включён. Для этой локальной проверки не нужно открывать порт 8080 в роутере или отключать брандмауэр.

Для настоящего многопользовательского рабочего запуска предстоит завершить предусмотренные ТЗ функции, выбрать сервер, настроить домен, HTTPS, безопасные cookies, доставку почты, 2FA, резервирование с восстановлением и контроль обновлений. Это следующая задача развёртывания, а не переключение одной строки APP_ENV.

## 24. Границы проверки этой инструкции

Команды запуска и имена сервисов сверены с реальными compose.yaml, Dockerfile, setup.mjs и серверной конфигурацией архива. Серверные сценарии первого этапа ранее прошли 11 автоматических проверок на MySQL 8.4.7, включая родительский тест.

Полный маршрут установки Windows и сборка через Docker Desktop на Windows в текущем окружении не выполнялись. Здесь нет Windows и Docker Engine. Поэтому инструкция не выдаёт проверку кода за подтверждённую установку на вашем компьютере. Диагностические шаги выше помогут проверить каждый этап у вас.
