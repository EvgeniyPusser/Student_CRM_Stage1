# Student CRM — реализация, этап 1

Основа: принятое ТЗ 1.3. Это первая серверная часть проекта, а не завершённая реализация всех требований.

## Что работает

React-клиент обращается к Express API по одному адресу. Express проверяет сеанс, CSRF и права, выполняет бизнес-операции и сохраняет данные в MySQL 8.4. Браузер не подключается к базе непосредственно.

В этой сборке есть настоящий вход по паролю, выход с отзывом сеанса, три роли, профиль с языком RU/EN, курсы, группы, состав с контактами для сотрудников, приглашение студента, зачисление и расписание. Для демонстрации создаются отдельные аккаунты администратора, преподавателя и студента. Публичного переключателя ролей нет.

Сеансы хранятся в MySQL. Идентификатор сеанса — случайное значение в HttpOnly cookie; в базе сохраняется его SHA-256. После входа идентификатор заменяется. Есть предел 12 часов и таймаут бездействия 2 часа. Пароли хешируются Argon2id: память 19 456 КиБ, 2 прохода, параллелизм 1. Изменяющие запросы требуют CSRF-токен и правильный Origin. Чужой объект возвращает 404.

## Модель первого этапа

| Таблица | Назначение |
| --- | --- |
| users, user_roles | Профиль, состояние аккаунта, хеш пароля и роли |
| sessions | Сеансы, сроки и CSRF |
| invitations | Хеш одноразового кода приглашения, срок 72 часа |
| courses | Курсы центра |
| study_groups, group_teachers | Группы и назначенные преподаватели |
| enrollments, enrollment_periods | Зачисления и отдельные периоды обучения |
| lessons | Занятия с UTC-временем и ссылкой/аудиторией |
| audit_events | Автор, действие, объект и история важных операций |
| schema_migrations | Применённые миграции и контрольные суммы |

Внешние ключи и уникальные ограничения созданы в MySQL. Миграции выполняются отдельной командой под блокировкой. MySQL DDL не считается транзакционным: при частичном сбое миграции запуск останавливается; для рабочей системы необходим отдельный план восстановления.

## Конкурентные операции

При зачислении сервер блокирует строку группы, проверяет вместимость и создаёт зачисление с периодом в одной транзакции. Уникальная пара студент–группа исключает дубликаты. При создании занятия блокируются группа и преподаватель; затем проверяются пересечения во всех его группах.

## Границы доступа

| Действие | Администратор | Преподаватель | Студент |
| --- | --- | --- | --- |
| Создать курс/группу/занятие | Да | Нет | Нет |
| Создать приглашение студента и зачислить | Да | Нет | Нет |
| Получить все группы | Да | Только назначенные | Только собственные зачисления |
| Прочитать состав с ID/email/телефоном | Да | Только назначенные группы | Контакты других не передаются |
| Прочитать профиль | Все | Собственный | Собственный |
| Расписание | Все группы | Назначенные | Свои группы |

Неделя определяется сервером по календарной дате Asia/Jerusalem, всегда с воскресенья по субботу, независимо от RU/EN. Занятия хранятся как UTC-моменты, календарные даты начала/окончания обучения — DATE. API создания занятия принимает дату со смещением Израиля и проверяет соответствие смещения зоне; несуществующее местное время отклоняется. Для неоднозначного времени смещение выбирается явно.

## Что ещё не реализовано

Полный жизненный цикл групп и зачислений, повторы расписания, переносы и отмены, посещаемость, учебные материалы и файлы, задания, финансы, отчёты, почтовая очередь, восстановление пароля, смена email, блокировка из интерфейса, управление ролями, 2FA, резервирование и развёртывание production остаются следующими этапами.

В этой сборке нельзя запустить APP_ENV=production: сервер намеренно останавливается, пока обязательные функции подготовки рабочего запуска отсутствуют. Нельзя использовать её с настоящими персональными и платёжными данными.

## Важное отличие от прототипа

Предыдущая веб-ссылка и автономный HTML остаются демонстрацией всех будущих экранов. Эта серверная сборка содержит ограниченный, но подключённый к MySQL набор экранов. Статический хостинг прототипа не запускает Express с MySQL. Рабочий этап запускается отдельно через Docker; публикация настоящей системы потребует сервера и HTTPS.
